## 🧩背景/情景 (Context)
> 当时遇到了什么问题？或者想到了什么？
- 25年的整个9月10月现金流感觉非常非常受限，我发现，其实一直对自己的消费习惯不了解：我是花钱大手大脚的人？还是一个勤俭的人？
- 为了更了解，为了让自己的钱💰更够花，我创建了一个Area —— Financial Health，并从10月15号开始推动这个方面的 —— 首先提取了一笔理财收入变成现金流，解我燃眉之急😆
- 接下来就对7-9三个月的消费记录进行数据分析 —— 详见notion页面：[7-9月消费记录分析报告](https://www.notion.so/7-9-29cc7f13487680daae27f696cc7ef5fc?source=copy_link)
- 分析结论是
	- 日常开支主要分为**系统型**和**事件型**
		- 详见[[什么是系统型和事件型支出]]
	- 要想保持现金流健康，需要一定程度上控制系统型开支，并且把事件型支出纳入管理
	- 要想纳入管理，首先要有管理，所以这个预算管理系统迫在眉睫

## 🧠思考与分析 (Thought & Analysis)
> Tips：“它让我怎么想？”比“它说了什么？”更重要，尝试用自己的话讲述
- 一个预算管理系统必须要包含以下几个功能：
	- 预算设置
	- 预算执行跟踪（本质上是现金流变动跟踪）
	- 预算分类
- 先说说**预算分类**
	- 必要性：不分类管理预算，相当于只跟踪现金流，过于着眼当下，看不到未来
	- 那么，预算如何做分类？与Gemini的讨论中，他提出两个点，一是按“属性”作为第一层分类指标，二是按照“消费意图”进一步区分。所谓**属性**其实就是指，这笔现金流变动是固定的还是可变的灵活的？是收入还是支出？进一步区分**意图**，是订阅支出还是餐饮的随机支出？
	- 为了统一和便于后续跟踪或制作Dashboard，预算和消费记录的分类(Category)势必需要采用一个共通的值集，于是我设计了一个**Master Data数据库Category**![[Pasted image 20251108162635.png]]
		- Name：分类名称
		- Level：值集为{"L1","L2"}，L1 - 属性分类；L2 - 意图分类
			- 属性分类用来从**宏观**复盘消费趋势
			- 意图分类用来从**微观**复盘具体消费情况
		- Parent Node：L2节点有唯一一个父节点
		- Child Nodes：L1节点有多个子节点
- 预算执行跟踪
	- 对我来说，预算事实上就是跟踪现金流变动 —— 事实上心里的最终目的是通过记录现金流变动结合预算来了解自己有多少的可灵活支配的现金流，进而缓解近几个月现金流紧张的**焦虑感**
	- 所以设计了一个比较基础的消费记录（事实上包含收入）数据库Transactions![[Pasted image 20251108163534.png]]
		- Date: 消费发生日期
		- Description: 消费记录描述
		- Category: 分类，引用上面说的Category数据库
		- Type: 值集{"Income","Expense"}，指示当前记录是支出还是收入
		- Amount: 记录变动金额
		- Belonged Budget: 根据Category自动获取所属的预算项
		- Remarks: 备注
- 预算设置
	- 基础数据库Budget![[Pasted image 20251108164700.png]]
		- Name: 预算名称
		- Period: 预算周期
		- Category: 分类，引用Category数据库
		- Parent Category: 汇总，根据Category找到父节点
		- Limit: 预算金额
		- Spent: 已执行金额
		- Remain: 可用余额
		- Transactions: 关联消费项记录
- 有了这三个数据库作为基础，要怎么低摩擦力地记账、对账、执行预算呢？
	- 日常记账通过Notion固定页面收集
	- 通过自动化脚本自动处理微信和支付宝流水记录，同时自动合并已记录的现金流变动，增量更新未记账的现金流变动
	- 结合Notion API自动执行写入Transactions数据库
