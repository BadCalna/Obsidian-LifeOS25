## Web 请求与响应
---
想象一下你访问一个网站，比如你打开浏览器输入 `www.example.com/blog/posts/1`。在这个过程中，后台究竟发生了什么呢？
1. **客户端发起请求 (Request)：**
    - 你的浏览器（**客户端**）会向 `www.example.com` 的服务器发送一个 **HTTP 请求 (HTTP Request)**。
    - 这个请求包含了你需要的信息：
        - **请求方法 (HTTP Method)：** 最常见的是 **GET** (用于获取数据，比如打开一个网页) 和 **POST** (用于提交数据，比如提交表单)。你打开网页就是 GET 请求。
        - **URL (统一资源定位符)：** 你要访问的地址，比如 `/blog/posts/1`。
        - **头部 (Headers)：** 包含了关于请求的元数据，比如你的浏览器类型、你接受的语言、Cookie 等等。
        - **请求体 (Body)：** 如果是 POST 请求，这里会包含你提交的数据（比如表单里填写的用户名和密码）。
2. **服务器处理请求：**
    - Web 服务器接收到你的请求后，会把它交给我们的 Flask 应用处理。
    - Flask 应用中的**路由**（比如我们刚才写的 `@app.route('/user/<name>')`）会根据 URL 匹配到正确的**视图函数**（比如 `greet_user(name)`）。
    - 视图函数开始执行它的逻辑：
        - 它可能会从 URL 中提取参数（就像你代码中的 `name`）。
        - 它可能会去数据库查询数据（比如查询 `name` 这个用户的信息）。
        - 它可能会进行一些计算或业务逻辑。
3. **服务器发送响应 (Response)：**
    - 视图函数执行完毕后，它会生成一个 **HTTP 响应 (HTTP Response)**，并返回给客户端（你的浏览器）。
    - 这个响应也包含：
        - **状态码 (Status Code)：** 告诉浏览器请求的结果。比如 `200 OK` 表示成功，`404 Not Found` 表示页面不存在，`500 Internal Server Error` 表示服务器内部错误。
        - **头部 (Headers)：** 包含了关于响应的元数据，比如内容的类型（HTML、JSON 等）、缓存策略等。
        - **响应体 (Body)：** 这是最重要的部分，包含了实际的内容，比如 HTML 网页代码、图片数据、JSON 数据等。
4. **客户端接收响应并渲染：**
    - 你的浏览器接收到响应后，会根据响应头中的内容类型（比如 `Content-Type: text/html`）来解析响应体。
    - 如果是 HTML，浏览器就会解析 HTML、加载 CSS 来美化它，再执行 JavaScript 来添加交互，最终把完整的网页呈现给你。
#### 类比
整个过程就像你打电话给餐馆点餐：
- **你 (客户端)**：发起请求（“喂，你好，我想点一份宫保鸡丁。”）
- **电话线/网络 (连接)**：传输你的请求。
- **餐馆 (服务器)**：接到电话。
- **厨房工作人员 (Flask 路由和视图函数)**：根据你的要求（宫保鸡丁）开始准备。
- **厨房工作人员 (视图函数逻辑)**：烹饪菜肴。
- **服务员 (服务器)**：把做好的菜（**响应**）送到你面前。
- **你 (客户端)**：收到菜，开始享用（渲染）。
理解这个**请求-响应循环 (Request-Response Cycle)** 是理解任何 Web 应用工作原理的基础。
